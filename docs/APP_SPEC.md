# 随心调色 · SuiTone 开发说明

> 2026-10-28 状态：用户已要求暂停产品修改，先审阅“AI 对话为主、直接调色为辅”的定位及界面简化。请先结合 [Agent 交接说明](AGENT_HANDOFF.md) 理解最新反馈、实测与待确认方案；本文保留的历史界面和优先级不能当作已获准继续实施的依据。

## 1. 为什么要做这个 App

修图引擎（`engine/`）已经能用，但现在只能通过和 Claude 对话来驱动。实际用下来有两个痛点：

1. 不能拖滑块实时看效果。每改一次就要等一轮出图，像「水再绿一点」这种微调，来回很慢。
2. 不能自己动手批量处理。选片、排顺序、导出，都要靠说。

App 的定位（2026-10-27 用户修订）：简单、强大的 AI 辅助照片调色工具，适用于不同题材与后续持续导入的照片。既能自然微调，也能得到明显的电影、胶片、复古等创作风格，不能将单个湖水案例的目标色作为所有照片的默认值。核心能力：

- AI 分区调色（水、天、土地、人分开调）
- 按每张照片的光影自动调整，让整组观感协调；必要时再同步区域目标色
- 常用预设按「自然微调／创作风格」两组组织，提供真实缩略图与强度调整
- 内置对话，调用本机 Claude Code 或 Codex，将调整建议转成可编辑参数
- 去杂物
- 出片信息条
- 导出 LUT 给达芬奇（最后阶段）

主流程：导入一张或一批照片 → 自动调整 → 选择风格、参考匹配或对话调整 → 微调、比较与撤销 → 导出。照片处理继续由本地 Python 引擎完成。目前对话发送文字与本地统计摘要，不发送照片像素；必须如实说明 AI 尚未直接看见画面。

## 2. 用户与场景

- 用户：编导 / AIGC 创作者，懂达芬奇调色的节点逻辑，不写代码。
- 典型场景：外出考察拍了几十张手机照片，要挑 9 张，调成统一的色调，加出片信息，发朋友圈或放进方案 PPT。

## 3. MVP 功能（按优先级）

开发顺序以最新用户反馈为准：先通用自动调整与批量工作流，再完善自然／创作风格、参考匹配、真实 AI 对话和基础编辑体验；随后完善裁切与输出流程；LUT 导出最后做。下表保留功能编号用于追踪，不再代表严格的实施顺序。

| # | 功能 | 交互 | 调用的引擎 |
|---|---|---|---|
| 0 | **参考图反推（核心入口）** | 把一张或几张参考图拖进来（电影截图、喜欢的照片都行），App 按区域学出颜色和影调：天对天、水对水、人对人、土地对土地。学出来的结果直接显示成下面调色面板里的滑块数值，可以在这个基础上微调，也可以导出成 LUT。可以指定「这张参考图只管水色」 | 新写 `engine/match.py`：用 SegFormer 给参考图和目标图分区，在 Lab 空间里按区域匹配均值、方差和亮度直方图，再换算成 `grade()` 的参数 |
| 1 | 导入 | 把文件夹或照片拖进窗口，支持 JPG、HEIC、RAW；自动逐张初调，底部显示选片条 | `grade.load`、`raw.load_raw`（HEIC 用 `sips` 转码） |
| 2 | 选片 | 缩略图上标星、排除；自动把相似的图标出来提示 | 缩略图哈希比较（新写） |
| 3 | 调色面板 | 按节点顺序排列的滑块：黑白点 → 去雾强度 → 对比 → 水色（拾色器，或 Lab 三个滑块）→ 天空色相 → 秋叶饱和；**改一下马上出预览**（用 1200px 的预览图） | `grade.grade(**params)` |
| 4 | 遮罩查看 | 开关按钮，把水、天、人的选区用半透明色叠在图上，方便判断识别有没有出错 | `grade.masks`、`portrait.skin_mask` |
| 5 | 参数同步 | 「应用到所有选中的图」：水色锁成同一个绝对值，去雾强度可以每张单独调 | 同上 |
| 6 | 去杂物 | 在图上框选，选模式：「按类别」或「框里除了天空都去掉」，点执行 | `inpaint.remove(box, classes, keep)` |
| 7 | 人像 | 开关「肤色保护」，加「磨皮」「提亮」两个滑块 | `portrait.protect_skin`、`retouch` |
| 8 | 出片信息条 | 开关，地点文字可编辑，其他信息自动读 EXIF | `info_bar.with_bar` |
| 9 | 导出 | 明确选择位置、尺寸和格式；默认导出副本，明确选择替换时才处理冲突。裁切是主动编辑操作；LUT 最后阶段提供 | `cli.py` 各子命令、`lut.fit` |
| 10 | 降噪 / 放大 | 编辑面板的「画质」：按当前、所选或整批应用，生成预览，可对比、撤销并保存到每张照片；导出沿用已确定的画质，不再临时选择 | `enhance.denoise`、`upscale` |

## 4. 技术架构建议

- **界面**：SwiftUI 原生 Mac App。可以参考用户已有的 Mac App 项目「小清 Qingo」（`Coding Project/mac-cleanup-manager`）的工程结构和设计规范。
- **引擎**：直接复用 `engine/` 下的 Python，**不要用 Swift 重写算法**。两种接法：
  - 简单版：每次操作调用一次 `cli.py`（子进程），参数用 JSON 传，结果读输出的一行 JSON。
  - 推荐版：后台常驻一个本地 HTTP 服务（FastAPI 或 Python 自带的 `http.server`），模型只加载一次；**每张图的遮罩算一次就缓存起来**，之后拖滑块只重算调色、不重新识别，预览才能跟手。
- **Python 环境**：用 `~/.cache/photo-edit/venv`；首次启动时检查模型是否存在，缺了就提示下载（地址见 `engine/README.md`，国内网络需要走代理 `127.0.0.1:7897`）。
- **预览性能**：先用 1200px 的图出预览，导出时再用全尺寸计算。目标是遮罩缓存后，拖一下滑块 1 秒内出预览。

## 5. 数据与图像质量边界（按最新反馈修订）

- 导入与自动调整不擅自改变构图；用户可通过明确的裁切操作改变构图，不将「不能裁切」当作产品限制或常驻口号。
- 不自动加编号、装饰线、邮戳、海报、梗文案。
- 编辑保留可回退的原始素材；导出默认新副本。替换现有文件需要明确选择和冲突处理，不将「不覆盖」当作界面宣传文案。当前实现仅有新版本文件夹导出，裁切与替换流程仍待完成。
- 调色不能出现色阶断层：全程用浮点数计算，输出前加 dither。引擎已经处理好，不要在 Swift 那边做二次压缩或二次调色。
- 照片像素不上传，图像处理在本地完成。用户发起 Claude Code／Codex 对话会使用对应服务的既有账号与额度，输入仅包含文字和统计摘要，不能将对话宣传为完全离线。

## 6. 验收用例

用 `cases/2026-10-27_西吉震湖/原图/` 里的照片：

0. 拖一张海边参考照片进来反推：结果的水色要接近参考图，同时远处的雾山不能被染青。参考图地点未经核实时，不标注为三亚。
1. 导入 9 张，显式加载该案例的历史调色参数，结果要和 `cases/2026-10-27_西吉震湖/定稿_发圈版v4/` 肉眼一致：水色统一，没有色阶断层，山脊没有白边。通用自动调整另外验收，不将湖水专用参数作为全局默认。
2. 打开 IMG_8457，框选右侧的绳子栏杆（大约 `box=(0.88,0.30,1,1)`），去掉以后补出来的草丛不能糊成一片。
3. 打开 `cases/2026-10-24_西夏陵与览山公园/原图/956c4f2511c0709a9c28ea309c7a3ae5.JPG`，用「框里除了天空都去掉」去掉信号塔；肤色保护打开时，套一个偏青的风格，脸不能发青。
4. 导出 LUT，在达芬奇里加载不报错。
5. 拖一下滑块，1 秒内出预览（遮罩已经缓存的情况下）。
6. 扩展测试使用公开照片与 RAW，覆盖人像、夜景、城市、逆光、雪景等；自动调整不启用案例专用水色／天空／土地目标。
7. 自然微调与创作风格均产生可编辑参数；风格互有区别、强度为零可还原、整批操作可整批撤销。
8. Claude Code 和 Codex 分别进行真实调用，核对实际数值、作用范围、取消与过期结果处理；问题咨询不能偷偷修改照片。
9. 在最小支持窗口及常用窗口尺寸检查欢迎页、单张、整批、对话与导出：中文标签不竖排，标题不相互挤压，按钮可读、可达。
10. 画质设置在编辑阶段调整：降噪和放大能预览、撤销、保存恢复；切换风格不丢失画质；批量改降噪不改变各照片的放大倍数。导出使用每张照片的设置，输出尺寸按各自倍数计算，不受旧版全局导出设置覆盖。

## 7. 设计参考与设计原则

### 7.1 借鉴对象（开发前先去这些软件里亲手用一遍对应功能）

| 借鉴自 | 学什么 |
|---|---|
| DaVinci Resolve | 节点思维：每一步是一个可以单独关掉的节点，前后对比是最常用的操作；参考帧 / Shot Match |
| Lightroom | 「选择天空 / 选择主体」一键选区，选区用半透明颜色叠在图上；同步设置；快照和历史记录；按一个键看原图 |
| Capture One | Normalize（吸一个参考颜色，把整批图统一过去）；风格叠加，每层有自己的透明度 |
| Pixelmator Pro / Photomator | Match Colors（反推）：交互最直接，这个功能就照它做 |
| Apple 照片 | 「光效」「颜色」总滑块，背后联动多个参数，需要时才展开细项 |
| VSCO | 每个风格只有一个「强度」滑块 |
| Halide / Darkroom | 照片是主角、界面元素最少的 Mac 原生质感 |

### 7.1b 开源参考（可以读代码、借鉴算法；先确认许可证，GPL 代码不能直接复制进闭源 App）

| 项目 | 借鉴什么 |
|---|---|
| darktable | 「scene-referred」工作流：先在线性空间做曝光和白平衡，最后再映射成显示图（filmic / sigmoid）；color calibration 模块；color equalizer 按色相分区调整 |
| RawTherapee / ART | RAW 去马赛克、高光重建、局部对比的实现 |
| OpenCV / scikit-image | 直方图匹配、导向滤波（反推和去雾会用到） |

不用 REA（reverse-engineer-anything）去拆商业软件：要借鉴的是交互，亲手用一遍就能看明白；商业软件的核心是 AI 模型，拆出来也用不了；而且用户协议禁止反编译。只有将来要兼容某个私有预设格式、又没有公开文档时，才为了兼容去分析它的文件格式。

### 7.2 设计原则

1. **照片是主角**：界面用中性灰（接近 18% 灰）；不用彩色背景、渐变、玻璃拟态，它们会干扰人对照片颜色的判断。
2. **永远可以退回**：编辑保留原始素材；每个节点都能单独关掉；按一个键看原图；有历史记录和快照。主动裁切和导出选项按实际工作流设计。
3. **由浅到深**：默认显示风格、参考匹配和少量通用滑块，区域与节点参数在高级调整里展开。不能由某一张照片限定入口。
4. **AI 透明**：选区可以叠在图上看；反推出来的东西必须变成滑块数值，不能是黑箱；识别不确定的地方要提示。
5. **一批图是一个整体**：对比方式包括「这张的前后」和「九张并排」两种；改动可以「应用到所有选中的图」。
6. **快**：拖滑块的预览要跟手（见第 4 节）。慢了用户就不想调了，这一点比功能多更重要。
7. **专业而直接的文字**：使用导入、自动调整、风格、参考匹配、对话调整等动作名称；删除演示口号、重复标签与底部格式清单。名称与图标独立设计，未确定前保留开发名。

### 7.3 反推功能的边界（要在界面里告诉用户）

- 只学颜色和影调，学不来光线方向和光比。参考图是傍晚侧光、目标是中午顶光，这种差别会有，界面要提示。
- 参考图里没有的区域（比如参考图没有水），这一项就不改。
- 反推结果是一个起点，不是终点，默认让用户再微调一下。

## 8. 不做（至少第一版不做）

- 精修人像（瘦脸、液化、美妆）
- 云同步、账号、分享
- 视频调色（视频走达芬奇加导出的 LUT）
