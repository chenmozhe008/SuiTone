## 近期补充（2026-10-31）

- **0.4.11 选区卡片只留一种强调色（用户点名）**：以前「点选」蓝底、「添加」绿底，同一张卡片两种颜色，看着像两种不同性质的按钮，用户要求「要么都用一个相同的颜色，要么都别要」。现在：① 所有选中态统一为 `ToolAccent.blue` 实底加亮边，和裁切页比例按钮同一套；`ToolAccent` 里删掉 green／orange，避免再被误用。② 「添加／减去」改为深色容器内的分段开关（`polaritySegment` + `ChipStyle(quiet:)`），不再是两块并排独立按钮——它本来就是同一开关的两个方向。③ 撤销一笔／清除与选法按钮统一用 `idleFill` / `idleBorder`（原来 0.26 对 0.22 深浅不一）。④ 笔迹列表里的小圆点标记改中性灰，卡片内不再出现第二种色相。绿色／橙色只保留在画布笔迹上（红＝添加、橙＝减去）。已在独立评审实例截图核对选区页与移除页；Swift 77 项、Python 97 项通过。

## 近期补充（2026-10-30）

- **0.4.10 裁切交互按 PS 的习惯收口（用户第二次点名）**：① 点「确定」不再跳页——以前 `finishCrop()` 会 `inspectorTab = lastMainTab`，裁完想接着拉直得再点回来；现在确定只 `commitCrop()`，人留在裁切页，换页由用户点上方页签（离开时 `InspectorView.onChange` 自动 commit）。裁切页右上角那个「完成」按钮同理去掉（它原来也直接跳页），换成「回车应用，换页点上方页签」的提示。② 画布左下角加裁切提示：框是整张时「在照片上拖一下，框出要保留的范围」，框定后「框内拖＝移动 · 四角四边＝改大小 · 框外拖＝重新框」——和 PS 的模型一致（满幅框内拖动＝重画新框）。③ `commitCrop()` 加了「框没变就不记历史」，连点确定不会把历史堆满。④ 裁切拖动层从「只盖照片矩形」改成「铺满整块画布」（`PhotoCanvas.cropDragLayer`，坐标从画布换算到照片，超出部分收进边界）——之前手落在照片外的灰底上完全没反应，很容易被当成「框拖不动」。④ **验收方式**：以前「拖不动」只能靠用户反馈，现在加 `-debugDrag "x0,y0,x1,y1;..."`（`Support/DebugDrag.swift`）往自己窗口 `NSApp.sendEvent` 注入真实鼠标事件——和手按下去走同一条路（命中测试 → SwiftUI 手势），不需要辅助功能授权；`-debugAction finishCrop` 用来核对确定后是否跳页。实测日志：整张时拖出 `[0.188,0.204,0.615,0.550]`、框内拖动只改位置不改尺寸、拉左上角缩到 `[0.291,0.302,0.513,0.452]`、框外拖重新框、确定前后 `页=crop` 且 `历史条数=1`。Swift 77 项、Python 97 项通过，新增 `CropCommitTests`。
- **0.4.9 修三处界面问题（用户点名）**：① 裁切拖不动——根因是进裁切页时框是整张画面，按下落在框内被判成「移动」，满幅框挪不动，等于没反应；现在裁切拖动全部由画布那一个手势处理（CropOverlay 只负责画、不接手势），框内拖＝重新框，框定后框内＝移动、四角四边＝改大小，光标跟着变。② 选区工具条原来浮在照片上方挡画面、选中态看不出来，改成右栏 SelectionToolsCard（蓝底选中、绿／橙区分添加减去），画布只留左下角提示。③ 旋转松手跳变——引擎 `geometry._largest_inside` 以前按「任意比例的最大内接矩形」裁，和界面里拖动时的「保持原比例放大盖住」不一致；现在引擎也保持原比例（并留 1 像素，避免 `rotate(expand=True)` 中心差半像素切出黑角），拉直范围收紧到 ±45°。裁切拖拽的命中与移动逻辑在 `CropGeometry`（纯函数，有测试）。实测：Swift 75 项、Python 97 项通过；裁切框、右侧面板在独立评审实例里截图核对，鼠标拖动本身因本机没有辅助功能权限无法脚本模拟，需用户点一遍。

- 导入照片不再执行智能初调，保持默认参数和原图；多选时以所选列表第一张作为当前预览，调整页说明风格缩略图和批量作用范围；页签顺序改为「调整／对话」。已在独立窗口用公开样片核对，并增加导入与多选测试。

## 1. 产品是什么

**说一句话或点一个风格，把一组照片调好；结果永远是可以继续拉的滑块，不是重画的图。**

用户要的两种结果：
- **自然**：轻量、真实，修正曝光和颜色，像“拍得好”而不是“修过”；
- **出片**：风格明显，发小红书、朋友圈惊艳，主要靠预设。

使用者分三步走：用户本人自用（现在）→ 开源 → 卖给别人。架构从一开始按三步考虑。

### 和市面产品的区别

| 类型 | 代表 | 问题 |
|---|---|---|
| 生成式 AI 修图 | Google 相册对话修图、Photoshop AI 助手接的 Nano Banana／FLUX、各种“文字改图”App | 整张图重画：细节会变、分辨率受限、一组照片不统一、改完不能拉滑块 |
| 参数式调色 | Lightroom、Apple 照片、醒图滤镜 | 强的难学，简单的不能用话说清复杂需求 |

**随心调色 = 用对话驱动参数式调色。** AI 看懂画面和意图，输出滑块数值和区域调整；原画质、原尺寸、一组能统一、改完能手调。生成式只用于去杂物这类必须补像素的场景（现有 LaMa）。

## 2. 借鉴什么

| 来源 | 做法 | 落到本产品 |
|---|---|---|
| Lightroom 快速操作 | 先分析照片，只给相关的一键调整：有人才出“人像”，有天空才出“天空” | **建议卡片**，替代固定的水／天空／土地／人物栏目 |

| Photoshop AI 助手（2026-03 公测） | 聊天面板；一句话串多步；在照片上画一笔再写要求；语音 | 对话面板；点／圈一块再说；一句话可执行多个操作；语音后置 |
| Photoshop 光线调整层 | 曝光、对比、高光、阴影、白色、黑色一组 | “光线”总滑块的展开内容 |
| Apple 照片 | 总滑块带多项、点三角展开、每组“自动”、按住看原图 | 调整面板结构 |
| 醒图 | 一键出片、收藏滤镜、参考图调风格 | “我的风格”：满意结果或参考图存成自己的预设 |
| VSCO／Apple 摄影风格 | 风格只有一根强度滑块 | 风格卡 |

**不借**：Photoshop 图层体系、Lightroom 图库管理、生成式整图重绘调色、美颜瘦脸液化、节点式界面（达芬奇思路只留在引擎内部）。

## 3. 界面

```
┌──────────────────────────────┬────────────────────┐
│ 画布上方：对比｜修复｜画质｜导出   │ [对话] [调整]        │
│                              │                    │
│          照片（主角）          │ 对话视图（默认）       │
│   点一下画面 = 选中该区域        │  建议卡片（按画面生成）  │
│                              │  对话记录＋实际改动     │
│                              │  输入框              │
├──────────────────────────────┴────────────────────┤
│ 选片条（多选 = 改动作用于所选）                          │
└──────────────────────────────────────────────────┘
```

### 对话视图（默认打开）
- 顶部 3–5 张建议卡片，按当前照片内容生成（“天空更通透”“提亮人物”“压一下高光”），点一下直接执行；照片里没有的区域不出卡片。
- 输入要求；或先在照片上点／圈一块再说；参考图拖进来 = “照这张调”。
- 每条 AI 回复列出实际改动（照片名、参数从几到几）和撤销按钮；被撤销后卡片标“已撤销”。改动后在照片上短暂高亮被改区域。

### 调整视图：一个面板三层，默认只显示第一层
1. **风格**：“自然”一组（智能、清透、柔和……）、“出片”一组（青橙电影、暖胶片、复古……）、“我的风格”。一根强度滑块。出片类风格带颗粒、暗角、柔光等质感，不只调颜色。
2. **总滑块**：光线、颜色、质感三根；点三角展开细项（光线 → 曝光／对比／高光／阴影／白色／黑色）。每组有“自动”。
3. **局部**：列出这张照片识别到的区域（不存在的不列），也可在照片上点选；选中后用同一套光线／颜色滑块，带羽化。

三层和对话改的是同一份参数：AI 改完，滑块同步移动到新位置。

### 通用规则
- 不做“简单／专业”模式切换。
- **批量**：删除顶部“整批／所选／当前”三段开关。默认改当前；选片条多选后改动作用于所选；另有“把这张的调整同步到…”。对话说“这几张都…”按所选执行。
- 修复、画质点了才进入对应模式，做完回到原视图。
- 出片信息条、尺寸比例、LUT 在导出窗口里。
- 双击滑块复位；按住画面（或快捷键）看原图。
- 照片永远最大；界面中性灰；不加口号、装饰、编号。

- 对外售卖时，自带账号方式要确认各家条款。

## 5. 技术地基：统一操作层

**这是第一件要做的事，后面全部依赖它。**

把所有编辑定义成一张操作清单：应用风格、改总滑块／细项、改某区域、参考匹配、修复（需选区）、降噪、放大、存为我的风格、撤销。
- 风格卡、建议卡片、滑块、对话**全部调用同一套操作**，写进同一个编辑事务和撤销栈。
- AI 只能调用清单里有的操作，清单就是 AI 的能力边界；一句话可以串多个操作。
- **AI 的回复依据执行结果生成**（成功几张、哪些因照片已被改动而跳过），不让模型先宣布成功。
- 分工：视觉模型理解意图和画面；SegFormer 出区域遮罩；Python 引擎处理像素。不让大模型出遮罩或改像素。
- 总滑块到细项的映射、风格的分区域处理，定义在 Python 引擎里，Swift 只显示。

### 已知问题（阶段 1，均已修复，留作背景）
1. **AI 撤销会连带退回画质**（读代码推断，未复现）：`WorkspaceAssistant.swift` 在发送时保存撤销前状态，返回时只比较调色参数、不比较画质。等待期间用户改了画质，撤销 AI 会把画质一起退回。先写测试复现。

## 7. 开发顺序与验收

每个阶段做完先跑验收，通过后再进下一阶段；涉及界面的阶段先出截图给用户确认。

**阶段 1 · 统一操作层 + 事务问题**
- 建操作清单，UI 与 AI 共用；修第 6 节四个问题。
- 验收：AI 能触发降噪、放大、修复（有选区时）、参考匹配；问题 1–3 各有一条自动测试且通过；`./script/test.sh` 全部通过。

**阶段 2 · AI 看图 + 两种接入 + 建议卡片**
- 引擎接口；自带账号补发图；接第一家 API；发图提示开关；执行后复看 1 轮；建议卡片。
- 准备 20 句固定测试话术（含局部“天空太灰”“人脸偏暗”，含“调成小红书那种胶片感”，含做不到的要求），覆盖人像、夜景、风景、逆光、城市 5 类公开照片。
- 验收：方向和区域都对 ≥ 16／20（用户人工打分）；做不到的不返回假操作、不承诺；回复中的改动与实际参数一致；建议卡片不出现照片里没有的区域。

**阶段 3 · 界面重排**
- 先出 3 张静态截图（对话视图、调整三层展开、局部选中）给用户确认，再实现。
- 验收：默认只见照片、选片条、对话；任何地方没有常驻区域栏目和节点面板；不看说明能走通“导入 → 点建议卡片 → 说一句话 → 撤销 → 选出片风格 → 展开光线细调 → 点天空调蓝 → 存为我的风格 → 导出”；滑块暖缓存预览 < 1 秒；最小窗口下中文不竖排、按钮可达。

**阶段 4 · 风格与视觉质量**
- 重做风格库：“自然”求真，“出片”求惊艳（颗粒、暗角、柔光）；“我的风格”保存与套用。
- 跑 APP_SPEC 第 6 节全部用例；风格在人像、夜景、逆光、RAW 上过一遍，用户肉眼确认。

**阶段 5 · 对外发行准备**
- 模型许可证核查：SegFormer 官方权重来自 NVIDIA，许可证疑似限制商用，先查清，必要时换可商用分割模型；LaMa、Swin2SR 逐个核对。
- Python 环境与模型打包、首次启动下载、签名公证；设置页管理账号方式和 API key。
- 导出尺寸比例预设（如小红书 3:4）；LUT 导出最后做。
