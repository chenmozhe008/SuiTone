# 随心调色 · 产品方向与开发顺序

> 2026-10-28 第三版，替代 AGENT_HANDOFF.md 第六节的“建议方案”。接手开发的 Agent 以本文为准；APP_SPEC.md 第 1–3 节的旧界面描述作废，第 5、6 节的边界与验收继续有效。
> 现状与证据细节查 AGENT_HANDOFF.md，本文不重复。

## 一句话定位

**说一句话或点一个风格，把一组照片调好；结果永远是可以继续拉的滑块，不是重画的图。**

用户要的两种结果：
1. **自然**：轻量、真实，修正曝光和颜色，像“拍得好”而不是“修过”；
2. **惊艳**：风格明显，发小红书、朋友圈能出片，主要靠预设。

使用者：自己用（现在）→ 开源 → 卖给别人用。

## 一、和别人比，我们站在哪

市面上的 AI 修图分两类：

| 类型 | 代表 | 做法 | 问题 |
|---|---|---|---|
| 生成式 | Google 相册“帮我修图”、Photoshop AI 助手接的 Nano Banana／FLUX、各种“文字改图”App | 模型把整张图重新画一遍 | 细节会变、分辨率受限、一组照片之间不统一、改完没法拉滑块微调 |
| 参数式 | Lightroom、Apple 照片、醒图滤镜 | 调曝光、颜色、蒙版等参数 | 功能强的（Lightroom）学习成本高；简单的（醒图、照片）不能用话说清复杂需求 |

**随心调色的位置：用对话驱动参数式调色。** AI 理解画面和意图，输出的是滑块数值和区域调整。好处是原画质、原尺寸，一组 9 张能统一，改完还能手动拉。生成式只用在去杂物这类必须补像素的地方（现有 LaMa）。

## 二、借鉴清单

### 要借的

| 来源 | 做法 | 落到我们这里 |
|---|---|---|
| Lightroom 快速操作（Quick Actions） | 先分析照片内容，只给这张图相关的一键调整：有人才出现“人像”，有天空才出现“天空”，风景照出现山／水／植被 | **解决区域栏目繁复的核心办法**：不列固定栏目，按识别结果给 3–5 个建议卡片 |
| Lightroom 自适应预设 + AI 蒙版 | 预设自动对天空、主体分别处理；蒙版有羽化、边缘滑块 | 风格预设按区域分别作用（天空压蓝、肤色保护），用户感觉只是点了一个风格 |
| Photoshop AI 助手（2026 年 3 月公测） | 聊天面板；可选“直接执行”或“一步步教我”；在照片上画一笔再写要求（AI Markup）；一句话串多步；支持语音 | 对话面板；在照片上点／圈后再说；一句话可执行多个操作；语音输入后置 |
| Photoshop“光线”调整层 | 曝光、对比、高光、阴影、白色、黑色作为一组 | 第二层总滑块“光线”的展开内容 |
| Apple 照片 | 一根总滑块带多项、点三角才展开、每组有“自动”、按住看原图 | 调整面板结构 |
| 醒图 | 一键出片、收藏滤镜、上传参考图调整风格 | “我的风格”：把满意的结果或参考图存成自己的预设 |
| VSCO／Apple 摄影风格 | 风格只有一根强度滑块 | 风格卡 |

### 不借的

- Photoshop 图层体系、Lightroom 图库管理：太重，不是这个产品的事。
- 生成式整图重绘：画质和一致性都不可控，不用于调色。
- 美颜、瘦脸、液化：不在范围内，AI 被问到时如实说做不了。
- 节点式界面：达芬奇思路留在引擎内部，不放到界面上。

## 三、界面怎么组织

```
┌──────────────────────────────┬────────────────────┐
│                              │ [对话] [调整]        │
│          照片（主角）          │                    │
│   画布上方：对比｜修复｜画质      │ 对话视图（默认）：     │
│   点一下画面 = 选中该区域        │  建议卡片（按画面生成） │
│                              │  对话记录＋实际改动    │
│                              │  输入框              │
├──────────────────────────────┴────────────────────┤
│ 选片条（多选 = 改动作用于所选）                          │
└──────────────────────────────────────────────────┘
```

**对话视图（默认）**
- 顶部 3–5 张建议卡片，按这张照片内容生成，例如“天空更通透”“提亮人物”“压一下高光”，点一下直接执行；没有天空就不出现天空卡片。
- 对话：说要求，或者先在照片上点／圈一块再说；参考图拖进来 = “照这张调”。
- 每条 AI 回复列出实际改动，带撤销；改动后在照片上短暂高亮被改的区域。

**调整视图**，同一面板三层，默认只显示第一层：
1. **风格**：两组。“自然”（智能、清透、柔和……）和“出片”（青橙电影、暖胶片、复古……）；加“我的风格”。一根强度滑块。出片类风格可以带颗粒、暗角、柔光等质感，不只是调颜色。
2. **总滑块**：光线、颜色、质感三根，点三角展开细项（光线 → 曝光／对比／高光／阴影／白色／黑色）。每组有“自动”。
3. **局部**：列出识别到的区域（只列存在的），也可在照片上点选；选中后用同一套光线／颜色滑块，带羽化。

**批量**：去掉顶部“整批／所选／当前”开关。默认改当前；选片条多选后改动作用到所选；另有“把这张的调整同步到…”。

修复、画质是画布上方的工具按钮，点了才进入；出片信息条、尺寸比例、LUT 放在导出里。

## 四、AI 接入

| 方式 | 谁用 | 说明 |
|---|---|---|
| 自带账号（本机已登录的 Codex／Claude Code 等） | 自己日常用；有订阅的用户 | 用用户自己的额度。保留现有实现，补上发图 |
| API key（用户自填） | 没订阅的用户、对外发行版 | 先接一家效果好的视觉模型，再做兼容层（OpenAI 兼容格式覆盖国内多家） |
| 本机视觉小模型 | 后置实验 | 审美判断弱、和现有三个模型抢内存、下载 2–3GB 以上；主线稳定后限时评测再定 |

- 两种方式共用一个“引擎”接口，设置里选。
- **都要看图**：每次附当前预览（长边约 1024px）、选区图、参考图；执行后把新预览再给模型看一次，必要时追调，最多 1 轮。首次发图前提示会发送到哪个服务，可关闭。
- 建议卡片也由同一个引擎生成（导入后后台跑一次并缓存），没配置 AI 时退回本地规则：按识别到的区域给固定卡片。
- 对外**售卖**时，自带账号方式要确认各家条款。

## 五、技术地基：统一操作层

所有编辑定义成一张操作清单：应用风格、改总滑块／细项、改某区域、参考匹配、修复（需选区）、降噪、放大、存为我的风格、撤销。
- 风格卡、建议卡片、滑块、对话都调用这同一套操作，写进同一个编辑事务和撤销栈；
- AI 只能调用清单里有的操作，一句话可以串多个；
- **AI 的回复依据执行结果生成**，不让模型先宣布成功；
- 分工：视觉模型理解意图和画面，SegFormer 出区域，Python 引擎处理像素。

## 六、开发顺序与验收

**阶段 0 · 整理现场（半天）**
- 当前工作区完整提交；APP_SPEC 为唯一规格，AGENT_HANDOFF／DESIGN_REVIEW／UX_REVIEW 移入 `docs/archive/`。
- 验收：`git status` 干净；新 Agent 读 CLAUDE.md → 本文 → APP_SPEC 就能开工。

**阶段 1 · 统一操作层 + 事务问题**
- 建操作清单，UI 与 AI 共用；总滑块到细项的映射、风格的区域分别处理定义在引擎里。
- 修三个问题：AI 等待期间改了画质，撤销 AI 会连带退回（`WorkspaceAssistant.swift` 只比较调色参数；读代码推断，先写测试复现）；撤销后对话卡片仍显示“已调整”；任务 ID 返回前点取消无效。
- 验收：AI 能触发降噪、放大、修复（有选区时）、参考匹配；三个问题各有一条自动测试；撤销后对话卡片标“已撤销”。

**阶段 2 · AI 看图 + 两种接入 + 建议卡片**
- 引擎接口；自带账号补发图；接第一家 API；发图提示开关；执行后复看 1 轮；建议卡片。
- 20 句固定测试话术（含局部“天空太灰”“人脸偏暗”，含“调成小红书那种胶片感”，含做不到的要求），覆盖人像、夜景、风景、逆光、城市 5 类照片。
- 验收：方向和区域都对 ≥ 16／20（用户人工打分）；做不到的不返回假操作；回复里的改动与实际参数一致；建议卡片不出现照片里没有的区域。

**阶段 3 · 界面重排**
- 先出 3 张静态截图（对话视图、调整三层展开、局部选中）给用户确认，再实现。
- 验收：默认只见照片、选片条、对话；没有常驻区域栏目和节点面板；不看说明能完成“导入 → 点建议卡片 → 说一句话 → 撤销 → 选出片风格 → 展开光线细调 → 点天空调蓝 → 存为我的风格 → 导出”；滑块暖缓存预览 < 1 秒。

**阶段 4 · 风格与视觉质量**
- 重做风格库：“自然”求真，“出片”求惊艳（加颗粒、暗角、柔光等质感）；“我的风格”保存与套用。
- 跑 APP_SPEC 第 6 节用例；风格在人像、夜景、逆光、RAW 上过一遍，用户肉眼确认。

**阶段 5 · 对外发行准备**
- 模型许可证核查：SegFormer 官方权重来自 NVIDIA，许可证疑似限制商用，先查清，必要时换可商用分割模型；LaMa、Swin2SR 逐个核对。
- Python 环境与模型打包、首次启动下载、签名公证；设置页管理账号方式和 API key。
- 导出尺寸比例预设（如小红书 3:4）、LUT 导出最后。

## 不做的事

- 不做“简单／专业”模式切换；不往界面加常驻栏目，新能力优先变成 AI 能调用的操作、建议卡片或展开后的细项。
- 不用生成式模型重画整张图来调色。
- 不把单个案例（湖水色）的参数当全局默认。
- 不在测试中覆盖真实原图；不悄悄上传照片。
