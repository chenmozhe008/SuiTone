# 随心调色 · SuiTone：复审与实施记录

> 后续状态：用户已要求暂停开发并让其他 Agent 把关，AI 对话现在被明确为主打功能。最新交接和待讨论方案见 [AGENT_HANDOFF.md](AGENT_HANDOFF.md)；下文是这一反馈之前的实施记录，不代表当前信息架构已获认可。追加的 12 项真实 CLI 检查及其边界也见交接说明。

本轮定位：照片是主角，常用操作直接可见，复杂选项按需展开，修改可比较、可撤销。当前属于开发阶段版，尚未通过 APP_SPEC 全部验收，不作为正式发行版。

## 整体判断

原界面把引擎参数当作产品工作流：修复藏在长面板底部，降噪和放大直到导出才选择，用户在编辑时看不到这些决定的效果。应按照「导入与选片 → 编辑并比较 → 输出」组织；调色、画质和修复都属于编辑，AI 是调整的另一种入口。

参考 Apple 照片的常用调整、比较、恢复原始效果，以及去除干扰物的直接操作方式。本项目保留自己的 SwiftUI 与 Python 引擎；这是交互取舍，不表示复制其专有算法。官方参考：[编辑基础](https://support.apple.com/guide/photos/editing-basics-pht304c2ace6/mac)、[去除干扰物](https://support.apple.com/guide/photos/remove-distractions-and-imperfections-pht5c38b77c5/mac)。

## 六步流程检查

| 步骤 | 当前状态与证据 | 剩余问题 |
|---|---|---|
| 1. 导入、选片与整批预览 | 五张不同题材照片实际导入：雪山、夜景、湖景、人像、海滩；保存及重开记录已实测 | 首张可交互速度、关闭恢复和持久化历史尚未完整验收 |
| 2. 风格、微调与参考匹配 | 两组共 16 款风格，强度与可编辑参数；中文横排、真实缩略图。参考匹配已有实现 | 本轮未重跑全部分区参考匹配视觉用例；所有风格在不同肤色、逆光和 RAW 上的视觉审阅仍待完成 |
| 3. 画质 | 降噪、原尺寸／2 倍／4 倍移到编辑面板；按当前、所选、整批作用，进入逐张记录与撤销；预览和导出共用 Python 处理 | 适屏预览不能替代原尺寸细节检查；大图放大耗时、细节涂抹及精确缩放检查仍待完成 |
| 4. 修复 | 独立入口；框选 → 生成预览 → 修复前后比较 → 保留或取消。真实栏杆案例已实测保留、撤销 | 当前是矩形选区；画笔、点选与缩放定位待完善；完整原尺寸修复导出需继续验收 |
| 5. AI 对话 | Claude Code／Codex 既有 CLI；本轮 Codex 在 App 内实际返回“连接正常，不调整照片”，未增加编辑事务 | 发生过一次连接失败；已区分认证、额度、版本和网络错误，仅确定的临时网络错误重试一次。单次成功不代表全部稳定性验收完成；目前 AI 接收统计摘要，没有看见照片像素 |
| 6. 保存与导出 | JPEG／PNG 原尺寸、ICC、源文件哈希检查通过；画质保存在每张照片上，旧记录兼容；导出沿用编辑状态 | 裁切、替换现有文件、更多位深／格式和发行打包仍未完成；LUT 保持最后阶段 |

## 本轮已修改

- 品牌统一为「随心调色 · SuiTone」，包括窗口、菜单、应用包和启动入口；保留用户选定的第五款光色环图标。
- 侧栏按「调色／修复／AI 对话」组织。常用调色直接可见，精细调整折叠。修复不再藏在节点参数中。
- 修复预览不提前修改照片：只有保留才产生一次编辑事务；取消、切换照片和过期结果均有保护。
- 「画质」位于微调之后。降噪和放大逐张保存，不再是全局导出开关；单独修改降噪会保留各照片原有放大倍数，反之亦然。换风格、参考匹配、修复与 AI 调色继续沿用画质。
- 画质结果单独缓存，修改调色参数不重新运行降噪、放大或语义识别。降噪通过差值保留浮点输入的亚色阶信息，最终输出继续使用抖动量化。
- 导出窗口移除降噪与放大，保留格式、出片信息和位置。出片信息属于输出排版，目前仍在导出设置中；编辑画布尚未提供信息条版式预览。
- 恢复调整记录后不再误显示“尚未应用自动调整”；无文字说明时显示“暂无调整说明”。目前记录尚不恢复原有风格名称和说明。

## 实测与边界

- Swift：7 项测试通过，覆盖修复取消、保留、过期结果、撤销重做，旧记录与逐张画质往返；release 构建和启动通过。
- Python：25 项测试通过，包括格式、区域隔离、参数约束、画质缓存、逐张导出、浮点精度和安全 CLI 错误处理。
- 实际 UI：夜景开启降噪成功，撤销后开关关闭，重做后开启。保存文件回读验证只有夜景 `denoise=true`，另外四张保持原设置，导出选项不包含画质字段。记录在 `tmp/ui-review-input/quality-ui-check-20261028.photoedit`。
- 真实模型：由公开夜景生成的 160×102 测试输入，降噪后原尺寸、2 倍、4 倍分别导出 160×102、320×204、640×408，均包含 ICC。区域推理计数始终为 1，源文件不变。首次预览约 1.35／7.01／4.72 秒（含首次加载），缓存后改变曝光约 6–9ms。此数据是小尺寸模型连通性检查，不能推广为全尺寸放大性能。报告：`output/ux-review-20261028/quality-model-check.json`。
- 公开夜景原生尺寸 JPEG／PNG：1920×1229，约 1.72／1.57 秒，源文件不变。报告：`output/ux-review-20261028/native-export-check.json`。
- 真实案例栏杆：`IMG_8457.HEIC`，框选右侧并使用“指定对象／栏杆与围栏”，已查看生成效果、修复前后、保留与撤销。与栏杆类别不同的细杆仍可能保留；不能据此声称任意杂物都能自动去掉。
- 当前存在 1002–1521ms 的首次／竞争状态预览记录，尚不能宣称所有 App 交互稳定低于一秒。历史 25 图、16 风格和暖缓存报告保留在 `output/workflow-20261027-231037/results.json`，不等同于本轮逐图视觉验收。
- 当前普通窗口已核对；全套最小窗口、键盘、VoiceOver、错误与复杂展开状态尚未验完，不宣称完整无障碍达标。

## 接下来的顺序

1. 编辑细节：缩放／原尺寸对比、画笔与更直接的修复选区，明确当前与整批作用范围，检查最小窗口和键盘可达性。
2. 质量与速度：补全真实案例、不同题材和 RAW 的视觉验收；调度缩略图与预览任务，解决超过一秒的交互。
3. 工作流闭环：裁切、输出尺寸与文件冲突处理，关闭恢复、历史及说明持久化，补齐失败与取消场景。
4. 交付：独立运行与签名打包；LUT 最后处理。
